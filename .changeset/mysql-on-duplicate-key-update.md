MySQL and MariaDB upserts: `insertInto(table).values(rows).onDuplicateKeyUpdate({ set })` writes `INSERT ... ON DUPLICATE KEY UPDATE`. `set` takes the forms `onConflictDoUpdate`'s does: a record of values, params or expressions, a callback `($, excluded) => ({ ... })` of the existing and proposed rows, `excluded(columns)` or `excludedAll(except?)`. MySQL reads the proposed row through a row alias, `VALUES (...) AS excluded` (MySQL 8.0.19+); MariaDB reads `VALUES(col)`. It fires on any unique key and takes no target or `where`, so `excludedAll` leaves out the table's declared primary key, and on a table with a `tenantColumn` the insert is `"cross-tenant"`. Reading a column of the proposed row that the insert does not write is an `InvalidArguments` error, since MariaDB's `VALUES(col)` would be NULL. `values` rows only; with `select`, on a table named `excluded` on MySQL, or on another dialect, compiling is a `QueryBuilderDefect`. `onConflict*` on MySQL now names `onDuplicateKeyUpdate` in its error, and `onDuplicateKeyUpdate` on Postgres or SQLite names `onConflictDoUpdate`. New: `Dialect.clauses.onDuplicateKey`, and the `OnDuplicateKeyUpdate` type.
