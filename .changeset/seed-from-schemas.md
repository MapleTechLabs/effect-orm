A new `/seed` entry makes test and demo rows from a table's column Schemas, through Effect's `Schema` → `Arbitrary`, with no dependency beyond `effect`. `rows(table, { count, seed })` returns decoded rows: the same seed gives the same rows, and each column samples from its own seed, so a new column does not change the others. The built-in column types add the range their SQL type stores (integer widths, `float4`, `DateTime` and `timestamptz` years, `uuid`, no U+0000 in Postgres `text`), and a branded column gets only values of its brand. `columns` overrides a column with a value, an `Arbitrary` (`pick(ids)` for a foreign key) or a function of the row index. `unique` columns, and a Postgres table's one-column primary key and `unique` columns, get distinct values. A table with a tenant column needs `tenant` (every row in one tenant, so the insert is `"single-tenant"`) or `crossTenant: true`. `insert(table, options)` writes the rows through `insertInto` on the `Database` in context, `batchSize` rows per statement, and `arbitrary(table)` gives whole rows to `Arbitrary.checkEffect` for property tests. Defaulted and computed columns are left to the database. Failures are a `SeedError`.
